# Voxel Tactics

A turn-based co-op tactics game in three.js: **XCOM 2** side phases, cover and overwatch, and **Phoenix Point**
free-aim ballistics with body parts, played on destructible voxel maps generated by **vibe-game's** world,
voxel and noise systems. Characters are 2D. Every committed action plays a **Chaos Zero Nightmare-style
back shot**: the character's large back-view illustration over an over-the-shoulder camera.

> Test build. All character art is **placeholder** (generated by `tools/art/make_placeholders.py`), and
> the animation code is a skeleton with marked TODOs. The battle rules, maps, destruction, elements,
> formations, AI, balance sim and online co-op work. See `docs/ANIMATION-AUDIT.md` and `docs/BALANCE.md`.

## Quick start

```bash
npm install
npm run dev            # http://localhost:5173  → menu
npm test               # 28 tests: voxels, elements, ballistics, battle, buildings, worldgen parity, co-op room
```

Deep links for testing:

| URL | What |
|---|---|
| `/?play=proving-grounds` | The test map with every system in it |
| `/?play=world:burg-15&seed=3` | A generated burg (any id from `client/public/missions/sites/index.json`) |
| `…&auto=1` | Squad plays itself (AI vs AI), useful to watch balance |
| `…&cutins=off` | Skip back shots (`always` / `first` / `off`) |

**Online co-op:** `npm run server` (port 2567), then *Host online co-op* in the menu and share the room code;
teammates use *Join*. Soldiers are dealt round-robin; the squad's turn ends when everyone has pressed End turn.
`npm run dev:all` runs client and server together.

## Controls

| Input | Action |
|---|---|
| Left click | select soldier · move (AP-coloured range) · fire / throw / overwatch in that mode |
| Right click / Esc | cancel mode · right-drag pans |
| `1`–`4` | weapons (shoot / melee mode) · **Z X C V G** aim at head / torso / L arm / R arm / legs |

## What the battle tests

- **Generated maps**: ten burgs from vibe-game's world (baked to `client/public/missions/sites/`), upscaled ×2,
  every building rebuilt hollow and multi-storey with rooms, **corridors**, doors, windows, stairs and roof access.
- **Targeting** (Phoenix Point): each shot fires real rays inside an accuracy cone; hit % per body part is a
  deterministic Monte-Carlo of the same tracer. Disabled arms cost accuracy, legs cost movement, head costs Will.
- **Cover**: physical — walls stop the rays that hit them; XCOM shields on the HUD read the voxels. Units lean
  out of corners. Flanking is simply having no wall in the way.
- **Destruction**: every voxel has hit points; bullets chip, bombs and powder kegs blast, unsupported floors and
  walls collapse into rubble, and units on vanished floors fall.
- **Interiors**: room reveal, dim rooms, noise through doors and walls, **breach** (door or charge) with surprise.
- **Voxel elemental system** (vibe-game's ELEMENTS on every voxel): fire ignites and spreads through timber and
  burns it down; water douses and wets; cold freezes water into walkable ice bridges and frozen ground; wind
  clears smoke and fans fire; earth concussion cracks stone.
- **Formations**: Shield Line, Breach Stack, Crossfire — with cohesion, costs, caps, static decay and the
  "clustered" blast counter. `npm run sim:formations` gates them.
- **Weapon balancing**: `npm run sim` runs AI-vs-AI battles and reports hit rates, damage per AP and kills per shot.
- **Stress / Breakdown** (CZN-inspired) and **Will points** (Phoenix Point) for abilities.

## Layout

```
shared/            deterministic rules (no DOM, no THREE, no Math.random) — run by client, server, sim, tests
  world/ util/ generation/ worldgen/ interiors/   ← copied from vibe-game (see PROVENANCE.md)
  voxel/           VoxelStore, Materials, Raycast (ported DDA), Destruction, Cover
  elements/        ElementField: fire, water, ice, wind, smoke; statuses
  mission/         ProvingGrounds, WorldSites (vibe-game generator → site), WorldMission, BuildingBuilder, Props, MissionMetrics
  battle/          Battle engine, Units, Ballistics, Formations, Ai
  content/         weapons, units, formations, balance tunables
  session/         scenario descriptors → missions/battles
client/src/        three.js client: render/ (chunk mesher, overlays, fx), units/, anim/ (skeleton), ui/, net/
server/src/        Colyseus 0.15 lockstep co-op room (vibe-game's backend pattern)
tools/             worldgen/bake_sites · sim/battle_sim · mission/report · art/make_placeholders
docs/              PLAN-01, ANIMATION-AUDIT, BALANCE, provenance.json, reference/vibe-game (audited originals)
```

## Useful commands

```bash
npm run sim                     # 24 AI-vs-AI battles on the Proving Grounds, weapon table
npm run sim:formations          # 100 seeds, formations on vs off, fails if the gates fail
npm run sim:world               # battles on every generated burg
npm run mission:report          # map-design metrics and gates for every mission
npm run worldgen:bake           # re-bake sites from the vibe-game generator (3–8 s each)
npm run art:placeholders        # regenerate placeholder art (python3 + Pillow)
```

## Status and known limits

- Art is placeholder; animation is frame-based with stubs (see `docs/ANIMATION-AUDIT.md`).
- Online co-op is lockstep: every peer runs the battle, so it is not cheat-proof and fog of war is client-side.
  PvP needs server-filtered state (PLAN-01 M13).
- Map gates are reported, not yet enforced with a repair pass (PLAN-01 §13.4).
- Roof access exists on single-storey flat roofs and keeps; two-storey corridor buildings have no roof stair yet.
